## 一份稿子从写到上线

1. **开写前读**：这一章的方向文件、章节文件里要写的那几站、`共同维护/设计口味.md`，还有 `待提交/` 里还没上线的稿：它们还不在章节文件里，后写的要和它们接得上。
2. **推敲**：用户说写哪个方向、哪张卡、哪一站。一次只写一个方向（意义 n + 例题 n）、一张卡或一站。先说思路，等用户提问，反复讨论；用户说「可以了」再写定稿。
   - 〔定义〕〔性质〕按站来：先给这一站的**推导链和分卡方案**（分几张卡、每张讲什么、从哪一步推到哪一步、哪些推不下去要进下一站），不要逐张贴「定位」清单；方案用户说可以，再一张一张写。
3. **自查**：按下面「交稿前自查」过一遍，查出问题先跟用户说。
4. **写进 `待提交/`**（格式见「交稿格式」），然后告诉用户：草稿箱里攒了几份、这一章还剩哪几个方向没写。
5. **改稿**：用户会把 Claude Code 的审稿意见贴给你。只改意见说的地方，直接覆盖 `待提交/` 里那份（文件名、开头几行不变）。拿不准、要用户定的先问用户；不同意的说出理由，由用户定。
6. **上线**：攒够了用户去找 Claude Code。上线后章节文件更新，那份挪进 `待提交/已提交/`。

**攒着上线，提醒用户**：Claude Code 那边额度紧，每次上线都有固定开销（测试、推送、更新镜像）。建议把这一章剩下的方向写完（或至少攒三份）再上线；审稿可以写好一份审一份。

## 格式规矩（网站上会显示错的，一条都不能犯）

- **不用反引号**：行内的和成块的代码格式都会变成灰底等宽字（用户不喜欢灰色），里面的 `#####`、公式原样露出来。公式用 `$…$`，步骤用列表。
- 不写 HTML 标签；不写引用附件留下的 `[cite: 1]`；正文里不写任何 `<!-- … -->` 记号行（记号由 Claude Code 用工具加）。
- 每行的 `$` 成对；独立公式写 `$$…$$`。手机上独立公式要放得下约 300px：长式子用 `aligned` / `cases` 拆行，附加条件写成文字。
- 标题：
  - 意义：`#### n. 方向名：一句话`；例题：`#### 例题 n：……`（一个意义配两道例题时写 `例题 n-1`、`例题 n-2`）；〔定义〕〔性质〕的卡照章节文件里现在的样子。
  - 一张卡里只有一个 `####`，卡里的小节一律 `#####`（意义的执行步骤写 `##### ❶`）；`####` 前面不加空格。
  - `######` 只用在〔定义〕〔性质〕教材末尾的 `###### 🧮 推导演示：……（和右边笔记对称）`，意义、例题里不用。
- 〔意义〕里「⚠️ 边界与避坑」前面单独一行 `---`。
- 列表外不要行首缩进 4 格（会变成代码块）；正文里不要整行加粗、以圈号开头的行（会变成站牌）。
- 想醒目：以 🎯🔑💡🚧⚠️ 开头的列表条目会变成彩色框，`==文字==` 是黄色荧光，`**标签**：` 是彩色小标签。荧光别满篇。
- 图片单独一段 `![图注](assets/images/…)`，图注里不写 `$`。表格最好三列以内（手机上列多会很高）。
- 意义 n、例题 n 的编号网站按位置自动算，照方向号写就行。

## 内容规矩（摘自设计口味，开写前读全文）

- **前提条件写全**（向量非零、不平行、直线不垂直于平面、分母不为零……）；每个数值、反例自己重算一遍（行列式、叉积、解方程、代回验算）；拿不准就直说。
- **意义**是逆向思考：遇到一类问题，去武器库里找哪件工具。依次写 🔍 问题、🎯 结论、💡 工具（只写名字和所属站，公式留在性质卡里）、⚙️ 执行步骤（决策树，`##### ❶`）、`---`、⚠️ 边界与避坑。每一步说清能拿到什么；走到头明说能力边界、转哪个方向。
- **例题**是把意义的决策树真走一遍：每个分叉至少有一道小题走到，至少一小题走到边界（停手、转方向）。有分叉的步骤写 👀 看到什么 → 🔀 有哪几条路、走哪条、为什么、另外几条为什么不走 → ✍️ 动手；走过场的一行带过；末尾不加一句话总结。
- **〔定义〕〔性质〕**（第 4 章重写时定下的）：
  - **教材只放最原始的**：定义、公式、运算律，严谨完整；推出来的结论（垂直、夹角、投影、面积……）放笔记，条件一条不丢。
  - **工具站**（公式玩不出花的站）一个工具一张卡：〔定义〕并进〔性质〕，这一站只在〔性质〕里。教材是「规整公式单」，每行「名称 + 一个公式」，同一个样子、不解释；笔记开头一行「🔑 一秒链」（如「面面：锁定 $\boldsymbol n_1, \boldsymbol n_2$ → 点积 → $\cos\theta$」），下面「题目给了什么 → 怎么办」小表和 ⚠️ 边界。
  - **笔记**讲清一个概念，不是知识清单：开头先定位；每节第一句就是核心；不复述左边教材；一节只讲一个「为什么」。
  - 左右两栏并排对照，长度要接近；笔记不长时不要加「🧮 推导演示」。
  - 一站推不下去的地方（「造不出垂直方向 → 下一站」），写明是下一站解决。
- **一件事只在一个地方**：别的站、别的方向（包括 `待提交/` 里没上线的）讲过的，只调用（名字 + 关键公式），不重讲；写「转入方向 m」时，方向 m 要真接得住。
- **不往后借**：本章没讲的工具不能用；要用就写明「见第 X 章」。
- 用推导讲懂，不用比喻代替推导（比喻最多一句引子）；不堆知识清单，不写为了全而全的边角料。
- 术语、记号照本章教材（向量坐标写 $a_1, a_2, a_3$），不借别科的词。
- 文风随意，网文词、口语都行；只是别把方法的能力说大（「唯一」「必然」「算不动」）。

## 交稿前自查

1. 「格式规矩」逐条对一遍，尤其反引号、`$` 成对、标题、⚠️ 前的 `---`。
2. 「踩过的坑」逐条对一遍。
3. 每个数值、每步推导重算；前提条件写全；逻辑方向没反；和本章〔定义〕〔性质〕不矛盾。
4. 和整章、草稿箱对照：有没有重讲别处的东西、用了本章没讲的工具、转入的方向接不接得住、术语记号一不一致。
5. 例题有没有走到意义里的每个分叉，有没有一小题走到边界。

文风、措辞不用查。

## 交稿格式

在 `待提交/` 里新建一个 `.md`，文件名写清是什么，如 `高数第4章-方向2-建平面与直线的方程.md`。一份文件交一件事。格式：

```
---
卡片: calc-vec-coordinates
操作: 追加意义例题
说明: 方向 2：建立平面与直线的方程
---

<!-- 意义 -->

#### 2. ……（意义 2 全文）

<!-- 例题 -->

#### 例题 2：……（例题 2 全文）
```

- **卡片**：卡片 id（见 `章节/目录.md`）。
- **操作**有三种：
  - `追加意义例题`：意义接在〔意义〕最后、例题接在〔例题〕最后，两半共用一个新记号（Claude Code 生成）。可以只交其中一段。同一章攒了几份时，按文件名排序依次接上，所以文件名里写上方向号。
  - `替换卡`：再加一行 `记号: xxxx`（章节文件里 `<!-- card:xxxx -->` 的那个 id），下面给 `<!-- 教材 -->`（或 `<!-- 意义 -->`）和 / 或 `<!-- 笔记 -->`（或 `<!-- 例题 -->`）的新全文，整张卡的这一半会被换掉。
  - `重写站`：〔定义〕〔性质〕整站重写（卡数可以变）。再加一行 `站: ①`（站的圈号），下面分四段：`<!-- 教材·定义 -->`、`<!-- 笔记·定义 -->`、`<!-- 教材·性质 -->`、`<!-- 笔记·性质 -->`，每段是这一站这一节的全部卡，一张卡一个 `#### n.` 标题，按顺序第 n 张教材和第 n 张笔记配成一对（两边卡数相同）。工具站只在〔性质〕里时，两段「定义」写一行「（无）」。站名行（如 `**① 从四面八方靠近**`）不用写；要改站名，在 `说明` 里写。这一项 Claude Code 手工接（结构改动），格式拿不准先问用户。
- 分段行 `<!-- 意义 -->` 等单独一行；这几行以外，正文里**不要写任何 `<!-- -->` 记号行**。
- 别的改动（跨站删卡、合卡、整节换掉、改站的划分）不走交稿文件，请用户直接找 Claude Code 说。
