## 一份稿子从写到上线

1. **开写前读**：这一章的方向文件、章节文件里要写的那几站、`共同维护/设计口味.md`，还有 `待提交/` 里还没上线的稿：它们还不在章节文件里，后写的要和它们接得上。
2. **推敲**：用户说写哪个方向、哪张卡、哪一站。一次只写一个方向（意义 n + 例题 n）、一张卡或一站。先说思路，等用户提问，反复讨论；用户说「可以了」再写定稿。
   - 〔定义〕〔性质〕按站来，分两段做（2026-10-19 起，第 5 章第③站开始）：
     1. **先只写教材**：先给这一站的**推导链和分卡方案**（分几张卡、每张讲什么、哪些推不下去要进下一站），不要逐张贴「定位」清单；方案用户说可以，只写这一站的教材，笔记段每张卡先写标题和一行「（待写）」，交进 `待提交/`，请 Claude Code 先审教材。
     2. **再压缩出笔记**：用户拿每张卡的教材去外面单独问，把看懂的长回答贴给你；你把它压缩成这张卡的笔记（规矩见「内容规矩」），覆盖 `待提交/` 里那份的笔记段。整站笔记写完，再请 Claude Code 审笔记。
3. **自查**：按下面「交稿前自查」过一遍，查出问题先跟用户说。
4. **写进 `待提交/`**（格式见「交稿格式」），然后告诉用户：草稿箱里攒了几份、这一章还剩哪几个方向没写。
5. **改稿**：用户说「审稿意见出来了」，就去读 `审稿意见/` 里和稿子同名的那份，看最下面一轮。只改意见说的地方，直接覆盖 `待提交/` 里那份（文件名、开头几行不变）。拿不准、要用户定的先问用户。改完在这一轮的「Gemini 回复」下面写几行：改了哪几条、哪条不同意（写理由）、哪条要用户定；意见文件的其他地方不动。
6. **上线**：Claude Code 审过以后，用户叫你上线，照「上线」那一节跑命令。上线后章节文件更新，那份挪进 `待提交/已提交/`。

上线不费 Claude Code 的额度（命令由你跑），审过的稿可以随时上；只是要按文件名顺序：排在前面的没审过，后面审过的也得等它。

## 格式规矩（网站上会显示错的，一条都不能犯）

- **不用反引号**：行内的和成块的代码格式都会变成灰底等宽字（用户不喜欢灰色），里面的 `#####`、公式原样露出来。公式用 `$…$`，步骤用列表。
- 不写 HTML 标签；不写引用附件留下的 `[cite: 1]`；正文里不写任何 `<!-- … -->` 记号行（记号由 Claude Code 用工具加）。
- 每行的 `$` 成对；独立公式写 `$$…$$`。手机上独立公式要放得下约 300px：长式子用 `aligned` / `cases` 拆行，附加条件写成文字。
- 标题：
  - 意义：`#### n. 方向名：一句话`；例题：`#### 例题 n：……`（一个意义配两道例题时写 `例题 n-1`、`例题 n-2`）；〔定义〕〔性质〕的卡照章节文件里现在的样子。
  - 一张卡里只有一个 `####`，卡里的小节一律 `#####`（意义的执行步骤写 `##### ❶`）；`####` 前面不加空格。
  - `######` 只用在〔定义〕〔性质〕教材末尾的 `###### 🧮 推导演示：……（和右边笔记对称）`，意义、例题里不用。
- 〔意义〕里「⚠️ 边界与避坑」前面单独一行 `---`。
- 列表外不要行首缩进 4 格（会变成代码块）；正文里不要整行加粗、以圈号开头的行（会变成站牌）。
- 想醒目：以 🎯🔑💡🚧⚠️ 开头的列表条目会变成彩色框，`==文字==` 是黄色荧光，`**标签**：` 是彩色小标签。荧光别满篇。
- 图片单独一段 `![图注](assets/images/…)`，图注里不写 `$`。表格最好三列以内（手机上列多会很高）。
- 意义 n、例题 n 的编号网站按位置自动算，照方向号写就行。

## 内容规矩（摘自设计口味，开写前读全文）

- **前提条件写全**（向量非零、不平行、直线不垂直于平面、分母不为零……）；每个数值、反例自己重算一遍（行列式、叉积、解方程、代回验算）；拿不准就直说。
- **意义**是逆向思考：遇到一类问题，去武器库里找哪件工具。依次写 🔍 问题、🎯 结论、💡 工具（只写名字和所属站，公式留在性质卡里）、⚙️ 执行步骤（决策树，`##### ❶`）、`---`、⚠️ 边界与避坑。每一步说清能拿到什么；走到头明说能力边界、转哪个方向。
- **例题**是把意义的决策树真走一遍：每个分叉至少有一道小题走到，至少一小题走到边界（停手、转方向）。有分叉的步骤写 👀 看到什么 → 🔀 有哪几条路、走哪条、为什么、另外几条为什么不走 → ✍️ 动手；走过场的一行带过；末尾不加一句话总结。
- **〔定义〕〔性质〕**（第 4 章定下，2026-10-19 第 5 章第③站改）：
  - **教材只有两种条目：定义、定理。** 定义是名词的标准定义（带记号）；定理是「条件 $\implies$ 结论（公式）」，条件一个不少。
    - 一条一个知识点：「**名称**：」打头，一两行写完；同一张卡里各条长得一个样（对仗），读起来像列表。数一数教材有几条，就知道这张卡有几个知识点。
    - 不写：为什么、怎么想到、讲法（如「一生二、二生四」）、例子、做题步骤和方法（两边求导、变量代换、怎么选路径）、避坑、从定理推出来的小结论（如 $f_{12}'' = f_{21}''$）。这些都进笔记。
    - 站引子一两句：这一站解决什么、从上一站哪里接过来。
    - 例：第 5 章第③站「高阶偏导数」的教材就三条：二阶偏导数（定义 + 记号）、混合偏导数（定义 + 求导先后）、求导次序无关（$f_{xy}, f_{yx}$ 在 $D$ 内连续 $\implies$ 相等）。
  - **笔记是压缩出来的**：用户拿每张卡的教材去外面单独问，把看懂的长回答贴给你；你把它压缩成这张卡的笔记，不另起炉灶重写。
    - 留：用户卡住的那个点、一句核心、推导的关键几步、一个小算例。
    - 删：和左边教材重复的；别的卡、别的站讲过的（改成一句调用）；口水话和夸大的话。
    - **外面的回答没人审过**：里面的结论自己核一遍，尤其条件（它说过「$f_{12}'' = f_{21}''$ 永远成立」，其实要二阶偏导数连续）。
    - 教材里没放的做题方法、避坑、推论，笔记里要接住，一样不丢。
  - **工具站**（公式玩不出花的站）一个工具一张卡：〔定义〕并进〔性质〕，这一站只在〔性质〕里；笔记开头可以先来一行「🔑 一秒链」（如「面面：锁定 $\boldsymbol n_1, \boldsymbol n_2$ → 点积 → $\cos\theta$」）。
  - 教材变短后，笔记会比教材长：两栏对齐由 Claude Code 上线时处理，写稿时不用为了对齐往教材里加东西。
  - 一站推不下去的地方（「造不出垂直方向 → 下一站」），写明是下一站解决。
- **一件事只在一个地方**：别的站、别的方向（包括 `待提交/` 里没上线的）讲过的，只调用（名字 + 关键公式），不重讲；写「转入方向 m」时，方向 m 要真接得住。
- **不往后借**：本章没讲的工具不能用；要用就写明「见第 X 章」。
- 用推导讲懂，不用比喻代替推导（比喻最多一句引子）；不堆知识清单，不写为了全而全的边角料。
- 术语、记号照本章教材（向量坐标写 $a_1, a_2, a_3$），不借别科的词。
- 文风随意，网文词、口语都行；只是别把方法的能力说大（「唯一」「必然」「算不动」）。

## 交稿前自查

1. 「格式规矩」逐条对一遍，尤其反引号、`$` 成对、标题、⚠️ 前的 `---`。
   - 〔定义〕〔性质〕的教材：每条是不是只有定义或定理、一两行、长得一个样；有没有混进讲法、例子、做题方法。
2. 「踩过的坑」逐条对一遍。
3. 每个数值、每步推导重算；前提条件写全；逻辑方向没反；和本章〔定义〕〔性质〕不矛盾。
4. 和整章、草稿箱对照：有没有重讲别处的东西、用了本章没讲的工具、转入的方向接不接得住、术语记号一不一致。
5. 例题有没有走到意义里的每个分叉，有没有一小题走到边界。

文风、措辞不用查。

## 交稿格式

在 `待提交/` 里新建一个 `.md`，文件名写清是什么，如 `高数第4章-方向2-建平面与直线的方程.md`。一份文件交一件事。格式：

```
---
卡片: calc-vec-coordinates
操作: 追加意义例题
说明: 方向 2：建立平面与直线的方程
---

<!-- 意义 -->

#### 2. ……（意义 2 全文）

<!-- 例题 -->

#### 例题 2：……（例题 2 全文）
```

- **卡片**：卡片 id（见 `章节/目录.md`）。
- **操作**有六种：
  - `追加意义例题`：意义接在〔意义〕最后、例题接在〔例题〕最后，两半共用一个新记号（Claude Code 生成）。可以只交其中一段。同一章攒了几份时，按文件名排序依次接上，所以文件名里写上方向号。
  - `替换卡`：再加一行 `记号: xxxx`（章节文件里 `<!-- card:xxxx -->` 的那个 id），下面给 `<!-- 教材 -->`（或 `<!-- 意义 -->`）和 / 或 `<!-- 笔记 -->`（或 `<!-- 例题 -->`）的新全文，整张卡的这一半会被换掉。
  - `重写站`：〔定义〕〔性质〕整站重写（卡数可以变）。再加一行 `站: ①`（站的圈号），下面分四段：`<!-- 教材·定义 -->`、`<!-- 笔记·定义 -->`、`<!-- 教材·性质 -->`、`<!-- 笔记·性质 -->`，每段是这一站这一节的全部卡，一张卡一个 `#### n.` 标题，按顺序第 n 张教材和第 n 张笔记配成一对（两边卡数相同）。
    - **站引子**：一段里第一个 `####` 前面的字，是这一站在这一节开头的引子（第 4 章写成 `> 💡 **本站定位**：……`）；不写就沿用现在的。
    - 工具站只在〔性质〕里时，两段「定义」写一行「（无）」，〔定义〕里的这一站整站删掉。只改〔性质〕、〔定义〕不动时，只交「性质」两段。
    - 站名行（如 `**① 从四面八方靠近**`）不用写。要改站名，开头再加一行 `站名: ④ 梯度：任意方向的变化率与切平面`（圈号打头、不加 `**`），两半所有小节里这一站的站名行都会换掉；〔定义〕开头「本卡主线」里的站名另交一份 `替换本卡主线`。
    - 卡和卡之间不用 `---`；旧卡、旧分组整站换掉，记号由 Claude Code 的工具生成。
