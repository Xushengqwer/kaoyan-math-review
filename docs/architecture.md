# 知识库重构：架构原则

重构任何章节的内容之前，先读完本文件。本文件只规定"怎么组织"，不规定具体数学内容。

## 0. 目标

把教材式的"按章节平铺的知识清单"，重构成"统一入口 + 分发器 + 公共函数"的系统。

衡量标准只有一个：做题时，从读完题干到确定解法路径，用时最短、出错最少。

## 1. 核心模型

用程序结构来理解每个模块：

- **入口（主线）**：一个模块只有一个入口，即一个核心问题或核心等式（先例：第 3 章卡② 以 $Ax = b$ 为入口）。每个知识点都要能回答：它在这个入口下处理的是哪一种输入。
- **分发器（分支）**：入口处按条件分到不同分支（先例：按研究对象分 A、x、b；x 再按 $b = 0$、$b \neq 0$ 分）。分支条件必须是做题时从题干能直接看出来的特征，否则分发本身就会变慢。
- **公共函数**：被多个分支调用的工具（先例：初等行变换、秩）单独成节，只写一次，各分支按名字调用，不复制内容。
- **章节是遗留接口**：教材原有章节只作参考，不构成约束。两章如果在处理同一个入口，就合并（先例：第 3 章卡② 吸收了第 4 章全部内容）。

## 2. 去冗余规则

- **单一数据源**：每个定义、定理、性质只存一处。其他地方需要它时，在「调用」里写它的名字，不重复内容，也不写"见第几条"这类位置引用。
- **区分两种冗余**：
  - 内容冗余：同一个结论写了两遍 → 删掉，只留一处。
  - 入口冗余：同一个结论的多种等价说法、多种触发条件 → 保留，集中列在一处（先例："$r(A) = n$ 的五种说法"）。考场上题目不会告诉你它属于哪个分支，多个入口是必要的。
- **合并判据**：两条内容如果能写成"同一个函数换不同参数"，就合并成一条母结论，再列出各参数下的特例（先例：向量组等价的三秩判据与方程组同解的三秩判据是同一个定理，一个横向拼接，一个纵向拼接）。

## 3. 卡片结构

沿用现有格式：

- **本卡主线**：入口加分支列表，几行说完。
- **〔定义〕**：按分支分组。
- **〔性质〕**：按分支分组；公共函数单独成组。
- **意义**：逆向的能力清单，按题型写，不挂在站里，见第 12 节。每个题型写四步：
  - 🔍 问题：遇到什么处境，写成题干里能直接看到的样子；
  - 🎯 结论：要得到什么，它是下一步任务的输入；
  - 💡 知识内容：用到的定义、性质，按名字写出关键式子；
  - ⚙️ 执行步骤：❶❷❸ 有序的操作，有分叉就写成分叉。

## 4. 无损重构（相当于回归测试）

重构不许丢知识点。每次重构必须同时产出两张表：

1. **迁移表**：旧卡里的每个知识点 → 新位置。删除的要写明理由（与哪一条重复，或超出考纲）。
2. **题型覆盖表**：旧版能处理的每类题，在新版分发表里由哪一类处理。找不到入口的，说明结构有漏洞，先报告，不要自己补结构。

## 5. 数学准确性

- 表述采用教材通行口径（同济版线性代数）。拿不准的地方标出来问我，不要自己编。
- 记号沿用现有约定：$A$ 为 $m \times n$ 矩阵，$n$ 为列数，即未知数个数。
- 合并时不许压掉前提、条件和反例（例："$r(A) < n$ 不能推出有无穷多解，必须先确认有解"）。

## 6. 什么时候改结构

结构为做题服务。只有出现下面三种情况，才改结构：

- 某类题在分发表里找不到入口；
- 某个分支条件从题干上看不出来；
- 同一内容出现在两处。

其余时候只改内容，不动结构。

## 7. 工作流程

- 先报计划：改哪几张卡、合并或拆分哪些、迁移表草稿。等我回复「开始」再动手。
- `assets/data/linalg.js`、`assets/data/notes.js` 等大文件不要整文件读取，用 grep 或 node 按 id 取需要的条目。
- 写入网站的文字，必须与我确认过的内容文件逐字一致。觉得有问题先问我，不要自己改。
- 改完先自检、先汇报，不要提交，等我确认。

## 8. 两种顺序

- 讲的顺序：〔定义〕〔性质〕按推导链排，每一条只用到前面已经出现的东西，不许跳跃；读完能从入口把整章推一遍。
- 查的顺序：意义（卡内分发表）和决策流（章内分发表）按题干特征排。两种顺序不混用。

## 9. 笔记

- 四层：〔定义〕〔性质〕〔例题〕〔提示〕；定义、性质与教材逐条对应。
- 保留我自己的建模与推导，写成「问题 → 推导」；用朴素的话，不用网文词，不写成教材的翻版。
- 借鉴旧笔记，取其精华、弃其糟粕：有灵气的部分（按自己的架构一点一点讲清楚的理解）吸收进来，不照搬，也不完全推倒重写。
- 例题优先大题分小题、共用一组数据；分叉处写成「若……」分支。
- 旧笔记是我的文字：迁移表要列出旧笔记每一段的去向；重写的内容先出草稿给我看。

## 10. 跨章调用

- 前面章节已有的结论（行列式、Ax = 0 的基础解系、秩、施密特、正交矩阵）不重写，只在「调用」里写名字；在「本卡主线」下列一行「依赖」。
- 发现跨章重复，按单一数据源处理，并写进迁移表。

## 11. 章级产物

- 计划里一并说明决策流、思维导图提示词、本章总结怎么处理。

## 12. 意义：逆向的能力清单（2026-10-06 共识，最重要的原则之一）

- **两种思考方向**：〔定义〕〔性质〕是正向——主动记住「是什么、有什么性质」。意义和例题是逆向——题目把你逼到某个处境，先抽象出任务，再去拿工具。做题、科研的真实顺序是逆向的，问题导向，所以意义是整张卡收获最大的部分。
- **检验标准**：合上书，能用一句话说出「学完本章，我能做什么」，并知道能力的边界在哪里。这句话就是本章意义的骨架。第 1 章：知道函数的性质，能判断极限存不存在，能判断函数连续还是有间断点，会求极限，能证明方程有根。说不出这句话，或者说出来的事在意义里找不到，意义就没写好。
- **任务序列**：数学问题是一串任务，上一层的结论喂给下一层的问题，有串行，也有组合。所以每个题型写四步：问题 → 结论 → 知识内容 → 执行步骤。
- **取舍**：只留反复出现、有执行步骤可练的逆向任务。只是检验懂不懂某个定义、现场能推出来的，不单独成题型（「记住定义，一力破万法」）。问题同源、只是处境不同的，合成一个题型，用分叉处理。
- **反过来检验正向**：〔定义〕〔性质〕里的一条，如果没有任何题型用到，多半是边角料，可以删。
- **写出边界**：本章工具在哪里用不下去，在执行步骤里明说，并指向后面的章（如「差的主部消不掉 → 泰勒公式，第 2 章」）。知道自己不会什么，和知道会什么一样重要；后一章的意义可以从前一章卡住的地方讲起。
- **例题**：演示核心动作，不炫具体函数的技巧。分层清楚、视觉负担低；本章的核心思路和具体函数的特性分开写（先例：第 1 章计算例题统一为 认型 → 化主部 → 结果 → 用到）。
- **视觉**：可以用小图标让层次更醒目；黄色重点要少而准，全局统一时再收。
