这是用户的考研数学复习网站（https://xushengqwer.github.io/kaoyan-math-review/）的内容镜像，给 Antigravity 里写稿的 AI（Gemini）读。审稿、提交、网站代码由另一边的 Claude Code 负责。

## 写稿

不需要素材包：直接读要写的那一章的文件，和 `共同维护/` 里这一章的方向文件（如果有）。开场白模板在 `共同维护/写作格式要求.md`，学习方法在 `规矩/学习方法.md`。用户说「可以了」以后，按下面「交稿前自查」过一遍，再按「交稿」的格式把定稿写进 `待提交/`。

**`待提交/` 里还没提交的稿子也要读**：攒着没交的方向还不在章节文件里，后写的方向要和它们接得上（不重讲它们的工具，「转入方向 m」时方向 m 真接得住）。

**审稿在 Claude Code 那边**：它审完、没问题就直接提交上线。那边额度紧，所以交稿前自己先查一遍，能少来回一轮。

## 交稿前自查

先读 `共同维护/设计口味.md`、`规矩/网站排版规则.md`，再对照要写的那一章的整个文件（全局视角就从这里来：稿子要和整章现在的内容、`待提交/` 里攒着的稿子对照着看）。按优先级查：

1. **会让人做错题的问题**：每一步自己重算（行列式、叉积、解方程、代回验算）；前提条件；逻辑方向；和本章〔定义〕〔性质〕矛盾。
2. **和整章不搭**：重复讲了别的站、别的方向已经讲过的东西（应改成一句调用）；用了本章还没讲的工具；「转入方向 m」时方向 m 接不住；术语、记号和本章不一致。
3. **和网站不搭**：`规矩/网站排版规则.md` 里「会原样露出来」的写法；标题格式；一张卡里多个 `####`；⚠️ 前缺 `---`；`$` 不成对。
4. **口味**：知识清单式堆砌、为了全而全的边角料、比喻代替推导、例题没走到意义里的某个分叉。

文风、措辞不挑。查出问题先跟用户说，用户定了再交稿。

## 交稿

用户说「可以了」以后，在 `待提交/` 里新建一个 `.md`，文件名写清是什么，如 `高数第4章-方向2-建平面与直线的方程.md`。一份文件交一件事。格式：

```
---
卡片: calc-vec-coordinates
操作: 追加意义例题
说明: 方向 2：建立平面与直线的方程
---

<!-- 意义 -->

#### 2. ……（意义 2 全文）

<!-- 例题 -->

#### 例题 2：……（例题 2 全文）
```

- **卡片**：卡片 id（见 `章节/目录.md`）。
- **操作**只有两种：
  - `追加意义例题`：意义接在〔意义〕最后、例题接在〔例题〕最后，两半共用一个新记号（Claude Code 生成）。可以只交其中一段。同一章攒了几份时，按文件名排序依次接上，所以文件名里写上方向号。
  - `替换卡`：再加一行 `记号: xxxx`（章节文件里 `<!-- card:xxxx -->` 的那个 id），下面给 `<!-- 教材 -->`（或 `<!-- 意义 -->`）和 / 或 `<!-- 笔记 -->`（或 `<!-- 例题 -->`）的新全文，整张卡的这一半会被换掉。
- 分段行 `<!-- 意义 -->` 等单独一行；正文里**不要写任何 `<!-- -->` 记号行**，不要反引号、HTML、[cite] 标记。
- 别的改动（删卡、合卡、整节换掉、改结构）不走交稿文件，请用户直接找 Claude Code 说。

**攒着交，提醒用户**：Claude Code 那边额度紧，一份一份交最费。每写好一份交稿文件，告诉用户 `待提交/` 里现在攒了几份、这一章还剩哪几个方向没写，建议把这一章剩下的方向写完（或至少攒三份）再去找 Claude Code 说「提交待提交」。Claude Code 一次审完、一次提交。

## 按审稿意见改

Claude Code 审出问题时，一份都不提交，把意见写进 `审稿意见/`，文件名和 `待提交/` 里那份相同。用户让你改时：读那份意见，只改意见里说的地方，直接覆盖 `待提交/` 里那份（文件名不变，开头几行不变）。意见里拿不准、要用户定的，先问用户。改完不用动 `审稿意见/`，Claude Code 下次只看改过的地方。
