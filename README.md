# 考研数学复习卡

覆盖高等数学（微积分）、线性代数、概率论与数理统计的核心内容，纯静态网页。每张卡分上下两块：上面是**教材**（〔定义〕〔性质〕〔意义〕），下面是自己写的**笔记**（〔定义〕〔性质〕〔例题〕〔提示〕，和教材一一对应）。支持：

- **知识手册**（`index.html`，唯一页面）：左侧固定导航栏，学科 → 章节两级树状结构，点章节后内容区按本章的「模块」分组展示，每个模块下是若干张卡。排版走简洁的图书排版风格（大留白、细分隔线，不是拥挤的卡片堆叠），支持本章内搜索和类型筛选。移动端导航栏收进抽屉菜单。
- **排版为背诵优化**：条目里的关键词、充要条件用**加粗**标出，最核心的结论句偶尔配一条下划线，天然有并列结构的内容（渐近线的三种情形、判别法、两类错误等）拆成分点列表，不是一整段文字堆在一起。
- **决策流与思维导图**：每章末尾依次是「决策流」（拿到题之后的判断顺序，按章写）、「思维导图」（一张图，页面上直接上传，原字节保存，随笔记一起导出提交）和「本章总结」。
- **右侧目录导轨**：每个章节页的右边缘常驻一条「本章目录」把手，鼠标移上去自动弹出、移开自动收起（触屏点一下钉住，再点收起，Esc 也能关）。页面顶部那份目录一往下滚就看不见了，这条一直都在，内容和顶部目录相同、实时同步。
- **章节目录**：每章开头有一份本章目录，按模块分栏列出全部卡片。每张卡下面还有「教材」「笔记」两行，列出这张卡实际有的小节（如 定义、性质、意义 / 定义、性质、例题、提示），小节是从原文的〔〕标题读出来的，改了结构目录自动跟着变；点卡片、点「教材」「笔记」或点小节，都直接跳到对应位置。写过笔记的卡会打一个小圆点（还没进仓库的点是橙色）。目录底部是决策流、思维导图、本章总结的入口。目录可折叠，且会跟随搜索和类型筛选同步。
- **全局搜索**：侧边栏顶部搜索框，一次搜遍全部知识点（含自己写的笔记），结果标注所属学科与章节、关键词高亮，点击直接跳转定位。
- **笔记**：每条知识点下方可以用自己的话写一遍理解，一律按 Markdown 显示，保存后提醒下载备份（存成 .md，文件名自动带出处，见下）。每条笔记都标着状态，一眼看出哪些还只存在浏览器里。写的时候点右上角**「放大」**可以全屏编辑（Esc 退出），小窗里改长笔记不方便。
- **本章笔记总结**：每章末尾有一块专门的总结区，整章读完之后用自己的话把这一章串一遍。存法、文件名规则和普通笔记完全一致（`本章总结` 作为位置标签），也能被全局搜索到。
- **导出本章 PDF**：每章末尾一个按钮，走浏览器自带的打印（目标选「另存为 PDF」）。不引第三方库——公式是矢量的、中文不会乱码、不依赖任何外部资源。点击时会自动清掉类型筛选和章内搜索、展开本章目录、收起正在编辑的笔记，保证导出的永远是完整一章；侧边栏、搜索框、按钮这些界面元素由打印样式表隐藏，条目和图不会被跨页切断。
- 只记"上次学习到哪一章"这一件事，保存在浏览器本地 `localStorage`，方便下次回来接着看；不需要注册登录，没有打卡/进度追踪之类的负担。
- 数学公式使用本地打包的 **KaTeX** 渲染，没有任何外部 CDN / 海外接口依赖，国内网络直接可用。
- 内置离线缓存（Service Worker），弱网/无网环境下已访问过的页面也能打开阅读。

## 本地预览

项目是纯静态文件，直接双击打开 `index.html` 即可使用（所有 JS/CSS/字体都是本地文件）。如果想用本地服务器预览（体验和线上一致）：

```bash
npx serve .
```

然后浏览器打开命令行提示的地址即可。

## 部署到 GitHub Pages

1. 在 [GitHub](https://github.com/new) 新建一个仓库，名字例如 `kaoyan-math-review`，**必须选 Public**（免费账号的 GitHub Pages 只支持公开仓库）。新建时**不要**勾选 "Add a README file" 等任何初始化选项，保持空仓库。
2. 在本项目目录下执行（`<你的用户名>` 换成你的 GitHub 用户名）：

   ```bash
   git remote add origin https://github.com/<你的用户名>/kaoyan-math-review.git
   git branch -M main
   git push -u origin main
   ```

3. 打开仓库页面 → **Settings** → 左侧 **Pages** → Source 选 **Deploy from a branch** → Branch 选 `main`、目录选 `/ (root)` → **Save**。
4. 等一两分钟，页面顶部会出现网址，形如：

   ```
   https://<你的用户名>.github.io/kaoyan-math-review/
   ```

   电脑、手机浏览器都能打开。手机上打开后可以「添加到主屏幕」，像 App 一样使用。

以后每次改了内容，只要 `git add . && git commit -m "..." && git push`，GitHub Pages 会**自动重新发布**，不需要手动点更新。

## 笔记怎么用

每条知识点下方都能用自己的话写一遍理解。笔记一律按 Markdown 显示（和教材内容同一套渲染）。

**写公式**：用 `$` 把公式包起来就会渲染成数学符号，例如输入 `$A\vec{v}=\lambda\vec{v}$`。整行的大公式用 `$$...$$`，会独立成行居中显示，太宽时自己横向滚动。

**加粗**：`**两个星号**` 之间的内容显示为加粗。

**Markdown**：可以把 AI 生成的 .md 原样贴进来，或用「导入 .md」按钮选文件。「### 〔定义〕名字」这类小标题按〔〕里的字自动上色，`==重点==` 显示下划线。注意 Markdown 里单个换行会并成一段，要分段请空一行。

> Markdown 与 LaTeX 的冲突（`x_1` 的下划线、`A^*` 的星号、`|A|` 的竖线）已经处理：渲染时先把 `$...$` 挖出来换成占位符，Markdown 跑完再放回去，所以公式里的符号动不到。原始 HTML 标签会被转义挡掉（防止一个 `<` 吞掉后面的内容），但 `&emsp;` 这类实体照常生效。

> 「导入 .md」只做一件事：**把文件内容原样填进输入框**，不解析、不转换、连换行符都不归一化。保存也不再做 trim，所以上传的 .md 与网站里存的内容**逐字节相同**。

> 保存前有一道体检：Markdown 最容易踩的坑是「缩进被当成代码块」，如果检测到会在编辑器里标出是第几行，保存时再确认一次。

编辑时点右上角「预览」可以先看完整渲染效果再保存，点「放大」可以全屏编辑（Esc 退出）。

> 关于安全性：笔记**以纯文本原样存储**，不做任何格式转换。`$` 公式渲染和 `**` 加粗都只发生在显示的那一刻，不会写回存储；导出的文件与你输入的内容逐字节相同（连首尾的空行、行末空格都不动）。所以不存在"编码转换把原文改乱"的可能。

笔记有两层存储：

1. **浏览器本地**（`localStorage`，key 为 `kaoyan_notes_v1`）：随写随存，离线也能写，但只属于这台设备的这个浏览器。
2. **仓库文件**（`assets/data/notes.js`）：提交进仓库后，任何设备打开都能看到，且有 Git 版本历史。

`localStorage` 本身没有过期时间，但下列情况会让第 1 层的内容消失，所以第 2 层才是真正的存档：

| 情况 | 会不会丢 |
| --- | --- |
| 关浏览器、关机、重启 | 不丢 |
| 清除浏览历史 / 缓存 / Cookie（勾了"网站数据"） | **丢** |
| 无痕模式里写的 | 关窗口就丢 |
| 换浏览器、换设备 | 看不到（不同步） |
| iPhone / iPad 的 Safari，连续 7 天没打开这个网站 | **被 ITP 自动删除** |

> iOS 上把网站「添加到主屏幕」当 App 打开，不受那条 7 天限制，手机上建议这样用。

因此每条笔记头部都会标出状态：

- **已进仓库** —— 和 `assets/data/notes.js` 里的内容一致，换任何设备都能看到。
- **未进仓库** —— 新写的，只存在这台设备的浏览器里。侧边栏会汇总还有几条，点「打包这些成一个 .md」可以把它们导出到一个文件里，每段带完整出处和 id，直接交出去就能提交进仓库。
- **本地已改** —— 仓库里也有这一条，但本地这一版和它不一样（你后来改过，或者仓库那版重新排过版）。这时笔记头部会多一个**「用仓库版」**按钮，点了就丢掉本地这一版、改用仓库里的（会先弹窗确认）。

> 判断"是否一致"时会忽略 `$` 定界符：笔记入仓库时唯一做过的改动就是给公式补 `$`，正文逐字未动，所以补过 `$` 的笔记不会被误报成"未进仓库"。两边内容一致时页面显示仓库那一版，公式才能正常渲染。

**每次保存后会弹窗提醒下载一份备份**，存成 .md，文件名自动带上出处，例如：

```
线性代数-第3章-卡②-Ax = b（A 向量组 · x 解 · b 目标）.md
```

文件头部写清完整出处和知识点 id，正文夹在一对注释标记之间：

````markdown
> **线性代数 · 第3章 向量空间与线性方程组 · 卡②**
> Ax = b（A 向量组 · x 解 · b 目标）　·　`la-vec-def-max-independent-set`　·　Markdown

<!-- ↓ 正文开始 · 到「正文结束」为止逐字节原样，请勿改动 -->

（你写的正文）

<!-- ↑ 正文结束 · la-vec-def-max-independent-set -->
````

> 卡片 id 是早期起的，和现在的标题不一定对得上（比如上面这张），但 id 一旦进了仓库就不再改：本地副本、导出文件和提交记录都靠它对应。

这个格式同时满足两件事：

- **预览好看**：HTML 注释在任何 Markdown 预览器里都是隐形的，头部是一个引用块（小方框），正文该怎么渲染就怎么渲染，公式照常出现。
- **切分不出错**：正文的起止是两行写死的标记（结束标记还带上 id），拿到文件按标记切，取出来的正文和网页里存的**逐字节相同** —— 不靠"看起来像"去猜边界，所以不存在切多切少、把原文改乱的可能。

> 标记与正文之间各垫了一个空行（保证任何渲染器都把注释和正文当成两个独立的块）。切回来时去掉这一前一后各一个空行即可还原，所以正文哪怕以空行开头、以空格结尾，也能一字不差地还原。

这样光凭这个文件就能定位到是哪一条，方便日后归档或直接交给别人帮你提交。侧边栏另有「导出」（JSON，含全部笔记，可再导入）和「导入」。

想把笔记固化进仓库时，把导出的内容按格式补进 `assets/data/notes.js` 再 `git push` 即可。格式很简单：

```js
registerNotes({
  "知识点的 id": "内容（纯文本，换行用 \n）"
});
```

> 每条必须是一个完整的字符串字面量，**不要**写成 `"..." + "..."` 拼接。id 在导出的 JSON 里能直接看到。

### 关于国内访问

`github.io` 在中国大陆的访问不稳定（DNS 污染，时快时慢），**需要科学上网才能稳定打开**。好在本项目内置了 Service Worker 离线缓存：只要用能连通的网络完整打开过一次，之后即使断网/不挂梯子，已缓存的页面也能继续阅读。

如果之后想换成国内直连的方案，网站代码完全不用改（纯静态），可以考虑：

- **腾讯云 EdgeOne Pages**：国内节点，免费额度 5G，默认域名 `xxx.edgeone.app` 免备案，需实名认证。
- **Cloudflare Pages**：免注册门槛低、不需要备案，国内访问时快时慢。
- **自己的服务器/虚拟主机**（阿里云、腾讯云轻量服务器、宝塔面板等）：把整个项目目录丢进网站根目录即可；绑自己的域名需要 ICP 备案。
- ~~Gitee Pages~~：个人版已于 2024 年下线，目前只对企业版开放，不要再考虑。

## 目录结构

```
index.html          唯一页面：左侧导航栏（学科→章节）+ 右侧内容区
sw.js                离线缓存 Service Worker
manifest.json         PWA 元信息（可"添加到主屏幕"）
assets/
  css/style.css       全站样式（侧边栏/内容区/图书排版风格/深色模式）
  js/
    data-loader.js     学科数据注册与查询
    storage.js        本地存储：笔记、教材改动、思维导图（IndexedDB）、上次学习到哪一章
    katex-init.js      KaTeX 渲染封装
    app.js           侧边栏导航 + hash 路由 + 全局搜索 + 本章目录 + 笔记/教材编辑 + 导出
  data/
    calculus.js       高等数学数据（按章节「模块」组织）
    linalg.js         线性代数数据（按章节「模块」组织）
    probability.js    概率论与数理统计数据（按章节「模块」组织）
    notes.js          笔记、决策流、本章总结（跟着仓库走的那一份）
    mindmaps.js       已提交的思维导图清单（路径、大小、SHA-256）
    superseded.js     进过仓库又被改过的旧版本指纹（本机旧副本自动清掉，不用手改）
  images/mindmaps/     各章思维导图原图
  vendor/katex/        本地打包的 KaTeX（css/js/字体），无外部依赖
  vendor/marked/       本地打包的 marked（Markdown 渲染，MIT），同样不走 CDN
tests/                 node 直接运行的回归测试（node tests/xxx.cjs）
CONTENT_SCHEMA.md      新增/编辑知识点时的数据格式说明（含可选 diagram 字段说明）
```

## 如何自己补充/修改知识点

打开 `assets/data/` 下对应学科的文件，参考 `CONTENT_SCHEMA.md` 里的格式说明，在 `items` 数组里加一条对象即可，`chapterId` 要对应文件里 `chapters` 数组中已有的章节 id。改完保存、刷新页面就能看到新内容；`git push` 之后 GitHub Pages 会自动更新线上版本。
